How It Works

Seven Stages. Every Transaction. Fully Auditable.

Cheap checks gate expensive ones. The behavioral monitor runs on 100% of transactions in under 100ms. Only anomalies hit the ML stack. Hard rules short-circuit before any model runs.

✓
Three independent scoring paths — hard rules, ML classifier, and behavioral monitor never share a failure mode
✓
Fail closed, not open — any component failure routes to human review, never silent auto-approval
✓
Every step audit-logged — inputs, retrieved context, model version, gating decision, case outcome
✓
Config-first — thresholds, rules, model versions are runtime config, not code. No redeploy to tune.

Didn't Find What You Were Looking For?

We've got more answers waiting for you. If your question didn't make the list, don't hesitate to reach out.

FinShield offers a comprehensive suite of compliance engineering services designed to help financial institutions detect, investigate, and report suspicious transactions, spanning the complete lifecycle from ingestion to regulatory filing. Our core capabilities include: Hard Rule Engine (deterministic compliance rules), Behavioral Monitoring (per-account anomaly detection), Agentic RAG + LoRA Classifier (ML-powered screening), Case Management (investigation workflow), SAR/STR Filing (regulatory reporting), and Circuit Breaker Resilience (graceful degradation).

Rules-only systems produce 90%+ false positive rates because they can't distinguish between unusual and suspicious. FinShield combines hard rules (for deterministic blocks like sanctions matches) with ML classification and behavioral monitoring. The behavioral monitor catches account-specific anomalies ("this user never withdraws this much") that static rules miss. The result: fewer false positives, faster investigations, and decisions you can explain to a regulator.

No transaction data, embeddings, or model inputs leave your infrastructure. The ML stack (LoRA classifier, RAG retrieval, behavioral scorer) runs entirely on hardware you control — whether that's your data center, a VPC, or our managed cloud deployment. We don't use third-party LLM APIs. This is a hard architectural constraint, not a policy.

Most teams have FinShield running in staging within 2–5 days. The API is REST-based with a Python SDK — integration is typically a few hundred lines of code. Production deployment with custom rules, policy documents loaded into the RAG index, and team onboarding takes 2–4 weeks depending on complexity. Enterprise deployments with on-premise infrastructure and SSO integration typically take 4–8 weeks.

Never. FinShield fails closed, not open. If the model server is unavailable, transactions route directly to human review with a degraded-mode flag. Each downstream dependency (model server, pgvector, Redis) has an independent circuit breaker. The dashboard shows real-time system health so your team knows exactly which paths are affected. Auto-approval due to component failure is architecturally impossible.

Credits are consumed per transaction based on the processing path. Rule-only transactions (no ML) cost 0.2 credits. Transactions that trigger behavioral monitoring cost 0.5 credits. Full pipeline transactions (ML classification + RAG retrieval + behavioral) cost 1.0 credit. Most transactions (80%+) are low-risk and cost 0.2–0.5 credits. Your blended cost per transaction is typically $0.001–$0.003 depending on your risk profile.
