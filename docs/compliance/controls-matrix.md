# Controls matrix

Each row is one control. **A** = automated: code enforces it and the test named under Evidence
proves it. **P** = procedural: someone has to follow a runbook. **A+P** = both. **PG** after a test
name means the test runs only against Postgres. See the [README](./README.md#regenerating-the-evidence)
for how to re-run everything. Not legal advice.

Paths are relative to the repo root. Test links point to the test file; the test function is named
after `::`.

## Count

17 controls:
- 9 are automated end to end: C-01, C-02, C-03, C-05, C-07, C-09, C-11, C-14, C-16.
- 8 combine automated parts with a procedural step: C-04, C-06, C-08, C-10, C-12, C-13, C-15, C-17.
- None is purely procedural.

The "not implemented" items (MFA, SSO, KMS, incident response, RTO/RPO, pen test) have no row,
because they have no control to describe. They are in [limitations.md](./limitations.md) and
answered "No" in [questionnaire.md](./questionnaire.md).
